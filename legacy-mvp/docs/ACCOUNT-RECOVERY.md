# 이메일 인증 및 계정 복구

## 이용 흐름
- 로그인 화면 → **비밀번호를 잊으셨나요?** → 가입 이메일 입력 → 코드 이메일 요청 → 받은 코드와 새 비밀번호를 입력합니다.
- 로그인 후 **내 프로필 → 이메일 인증**에서 코드를 요청하고 붙여넣습니다.
- 이메일과 화면은 한국어·영어·일본어를 지원합니다.
- 재설정 성공 시 모든 기기의 서버 세션과 푸시 등록을 해제합니다. 새 비밀번호로 다시 로그인하고 기기 알림을 다시 활성화합니다.
- 코드는 15분간 유효하며 한 번만 사용 가능합니다. 코드는 링크를 누르는 방식이 아니라 앱 화면에 붙여넣는 방식입니다.

## 서버 연결
서버의 `RESEND_API_KEY`와 `EMAIL_FROM`을 설정합니다. `EMAIL_FROM`에는 발송 서비스에서 인증한 도메인의 주소를 사용합니다. 키를 앱 번들이나 `EXPO_PUBLIC_*` 환경변수에 넣지 않습니다.

서버 진입점 `server/index.mjs`는 `APP_ENV=production`이면 이메일 인증을 필수로 적용하며, 발송 설정이 없으면 시작을 거부합니다. 개발/스테이징에서도 `REQUIRE_EMAIL_VERIFICATION=true`로 같은 흐름을 검증할 수 있습니다. 운영 환경에서는 이 변수를 false로 설정해도 인증이 필수입니다. 인증은 이메일 소유 확인이며 실명·성인·셀카 인증이 아닙니다.

코드 발송은 기존 15초 주기 작업에서 처리됩니다. 요청은 SQLite에 저장되어 서버 재시작 후에도 처리됩니다. 계정·용도별 요청은 1분에 한 번, 한 시간에 최대 5회로 제한합니다. 실패한 발송은 1분 간격으로 최대 3회 시도하며 실패한 코드는 폐기됩니다. 실제 전달 여부는 발송 서비스 로그를 확인합니다. `/auth/password/request`는 가입 여부와 무관하게 같은 접수 응답을 반환합니다.

메일 발송 계정이 연결되지 않았다면 준비 중 안내를 표시합니다. 성공한 실제 이메일 발송이나 수신함 도착을 이번 검증으로 보장하지 않습니다. 발송 실패 테스트는 의도적으로 오류 로그를 생성합니다.

## 검증
- `cd server && npm test`: 토큰 해시 저장·만료·재사용 차단·동시 소비 방지·용도/소유자 분리·모든 세션/푸시 해제·이메일 비공개·발송 실패 재시도 검증.
- `cd mobile && npm run typecheck && npm run lint`
- `cd mobile && npx expo export --platform web`
- 프로젝트 루트에서 `CHROME_PATH=/path/to/chromium node scripts/ui-account.cjs`: 임시 데이터베이스와 메모리 메일함을 사용하는 화면 검증. 실제 메일을 보내지 않습니다.
