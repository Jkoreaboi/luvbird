# 첫 사용자 경험과 출시 준비 — 2026-09-26

## 판단
코드에서 가입·펜팔 요청/수락·사진 편지·24시간 도착을 실행할 수 있다. 그러나 현재 산출물만으로 신규 사용자를 바로 받을 수 있는 공개 서비스는 아니다. 실제 API 서버·이메일 발송·설치 배포·운영 연락처가 연결되고 실기기 검증을 거쳐야 한다.

## 이번 수정의 기준
DearBird는 사진과 편지로 일상을 나누며, 서로의 속도를 존중하는 제품이다. 즉시 답장/수락을 약속하지 않는다. 읽음 표시·접속 상태·가짜 사용자·자동 상대 응답을 추가하지 않았다. 사진 없이 짧은 자기소개로도 첫 편지를 시작할 수 있다.

## 첫 사용 흐름
1. 가입: 목적, 선택 도시, 언어와 자기소개를 입력한다. 만 18세 이상 확인.
2. 첫 지도 상단: 인증이 필요하면 이메일 인증으로 안내한다.
3. 펜팔: 다른 사람의 프로필을 보고 요청한다. 아직 사용자가 없으면 그 상태를 안내한다.
4. 보낸 요청: 수락 대기 상태와 취소 버튼을 제공한다. 취소해도 하루 3회 요청 한도는 복원하지 않는다.
5. 수락 후: 첫 편지 쓰기로 안내한다. 받은 요청이 있으면 요청 확인을 먼저 안내한다.
6. 발송 후: 24시간 배송/최소48시간 왕복을 안내하고, 받은 편지가 도착하면 봉투 열기로 연결한다. 과거에 도착한 편지도 포함하며 읽지 않은 편지 수를 표시하는 기능은 아니다.

## 안정성 변경
- 일시적인 시작 시 연결 실패는 로그인 정보를 보존하고 재연결 화면을 표시한다.
- 서버 세션이 만료/해제되면 이전 계정 화면을 정리하고 로그인으로 돌아간다.
- 네트워크 오류·응답 형식 오류·요청 제한 오류를 사용자가 이해할 수 있게 안내한다.
- 취소된 요청의 수락과 지연 푸시를 막는다.
- 운영 진입점은 이메일 인증을 강제한다. 발송 설정이 없으면 시작하지 않는다.
- 작동하는 가입/설치 링크가 없던 초대 버튼을 제거했다.

## 공개 전 반드시 연결할 항목
| 항목 | 현재 상태 | 완료 기준 |
|---|---|---|
| 운영 API/DB | 배포 구성만 있음 | HTTPS 서버와 영구 디스크 연결, 백업/복원 확인 |
| 이메일 | 코드·모의 발송 검증 | 실제 발송 도메인과 키 연결, 실제 두 이메일로 인증·복구 성공 |
| 앱 배포 | 소스/JS 빌드 검증 | EAS 프로젝트와 서명 연결, APK 설치 또는 TestFlight 초대 성공 |
| 알림/실기기 | 코드만 검증 | 두 기기에서 권한·백그라운드·오프라인·푸시 확인 |
| 운영/지원 | 테스트 안내 | 실제 문의 연락처와 운영 주체, 신고 처리 담당, 적용 정책 확정 |
| 초기 펜팔 | 자동 생성하지 않음 | 서로 편지 교환에 동의한 실제 초기 사용자 모집 |

위 연결이 끝나면 소규모 초대 테스트로 시작한다. 상대가 아직 없는 상태에서는 첫 실제 편지를 교환할 수 없으므로 초기 사용자 모집을 제품 준비와 함께 진행해야 한다.

광고·유료 결제·셀카 인증·자동 매칭·대규모 페이지네이션은 이번 범위에 포함하지 않았다. 현재 목표는 첫 실제 편지 교환의 완주다.

## 배포 준비 추가 결과
운영 설정은 `render.yaml` 또는 `compose.yaml`, 실행 순서는 `release/DEPLOYMENT.md`에 준비했다. 현재 테스트26개 통과, 백업을 앱으로 복구해 로그인/사진 데이터를 확인했다. 실제 서비스 배포와 이메일 수신/실기기 설치는 계정 연결 전이므로 미완료다. Render 구성은 유료 컴퓨트/영구디스크를 포함하며 서비스는 아직 생성하지 않았다.

신고 운영 화면은 구현·테스트 완료했으며 실제 서버에서 운영 키 설정 후 사용한다. 첫 편지 질문/초안 복원, 공통점 표시, 빈 목록 프로필 작성 안내도 추가했다.
