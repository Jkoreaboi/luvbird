# 신고 처리 운영 화면

서버 환경 변수 `OPERATIONS_TOKEN`을 설정하면 `/ops`에서 접속한다. 설정하지 않으면 운영 경로는 비활성화된다. 공개 서버에서는 HTTPS를 사용한다.

## 설정

`openssl rand -hex 32`로 별도의 운영 키를 만들고 서버의 비밀 환경 변수에 저장한다. 32자 미만 값은 서버 시작을 거부한다. 앱의 EXPO_PUBLIC 변수나 소스 파일에 키를 넣지 않는다. Render에서는 Environment에 직접 추가한다. Compose는 OPERATIONS_TOKEN을 전달하도록 준비되어 있다.

운영 키를 입력하면 미처리/검토 중/처리 완료/기각/전체 목록을 50건씩 볼 수 있다. 키는 브라우저 저장소에 기록하지 않고 현재 페이지 메모리에만 유지된다. 접속 종료나 새로고침 후 다시 입력한다. 키를 변경하려면 서버 환경 변수를 교체하고 재시작한다.

## 처리

- 신고 사유, 신고자·대상 닉네임, 신고 시각과 조치 이력을 확인한다. 일반 편지 내용이나 비밀번호·이메일 주소는 운영 화면에 노출하지 않는다.
- 검토 중/처리 완료/기각/미처리로 변경할 때 판단 근거 메모를 남긴다.
- 계정 이용 제한/해제에는 별도 확인이 표시된다. 메모 없는 조치는 거부한다.
- 이용 제한은 로그인과 인증된 API 접근을 막고 기존 세션 및 알림 기기를 해제한다. 탐색 목록과 상대 연결에서도 숨긴다. 데이터 자체는 삭제하지 않는다.
- 제한 해제 후 사용자는 다시 로그인해야 한다. 사용자 간 차단은 해제되지 않는다. 제한 중 보류된 기존 관계·편지는 다시 보일 수 있다. 이용 제한을 영구 삭제나 편지 취소와 혼동하지 않는다.
- 같은 신고를 동시에 처리하면 먼저 저장한 결과를 보존하고 오래된 화면의 저장을 거부한다. 새로고침 후 다시 검토한다.

신고 이력과 이용 제한 데이터는 SQLite에 저장되어 기존 백업 대상에 포함된다. 이 화면은 단일 운영자용 키 방식이다. 여러 담당자의 개별 계정·MFA·담당자별 감사 추적은 포함하지 않는다. 기존 `moderate.mjs` CLI는 비상 직접 DB 도구이며 웹 이력을 우회하므로 일상 처리는 `/ops`를 사용한다.

## 검증

일반 사용자 토큰/잘못된 운영 키 거부, 상태·메모·충돌 방지, 이용 제한 및 해제, 재로그인, 목록에서 숨김, 신고 문자열의 HTML 실행 방지와 로그아웃 후 화면 정리를 테스트했다. 실제 운영 계정이나 실제 신고에는 적용하지 않았다.
